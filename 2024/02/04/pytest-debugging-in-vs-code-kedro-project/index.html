Pytest Debugging in VS Code (Kedro Project)

Feb 4, 2024
Tags: #Python #vscode #pytest #kedro
Table of Contents
  1. Problem No. 1: ModuleNotFound
  2. Problem No. 2: Debug/Run single Test
  3. Problem No. 3: Make Debugging Work in VS Code

Recently, I started a Machine learning projects with the Kedro Framework. Based on the example spaceflights project, kedro uses the pytest library for unit testing. For a nice development workflow, I wanted to see the following requirements fulfilled:

  • Unit testing with Pytest library
  • Import module src folder
  • Ability to debug single file

Sounds simple, but there is some specific configuration necessary to make it work…

Problem No. 1: ModuleNotFound

For the purposes of this post, the relevant part of project structure looks like this:

project/
├── src/
│   └── pipelines
└── tests/
    └── test_pipelines

This means that when testing the modules in the tests/pipelines folder, the python scripts inside the src/pipelines module need to be found by pytest. Pytest scanns the code for test files to be executed. Given the folder structure, Pytest by default does not find the modules in the src folder. In order to let Pytest discover them, the following setting is needed in the pyproject.toml (see also this SO post for more info).

[tool.pytest.ini_options]
pythonpath = [
  ".", "src",
]

Problem No. 2: Debug/Run single Test

Assuming Python Debugging is generally already working (if not install the Python VS Code plugin and follow the VS Code Guide) Hit Ctrl + Shift + D to open the debug window. The Running/Debugging can be customized by creating a launch.json configuration file.

In order to run/debug Pytest a single file, we can pass the predefined vs Code Variable as an argument "${file}" to the python. With this setup the currently selected file will be run when clicking the run/debug buttons.

Problem No. 3: Make Debugging Work in VS Code

You may notice that even when a Breakpoint is set, the debugger does not stop at the specified position. This is because the debugging does not work with Pytest coverage on (As pointed out here). This can be fixed by passing the "--no-cov" parameter to Pytest.

In total your lanuch.json should now contain a configuration like this:

        {
            "name": "Pytest: Debug File",
            "type": "python",
            "request": "launch",
            "module": "pytest",
            "args": [
                "${file}",
                "--no-cov"
            ],
            "console": "integratedTerminal",
            "env": {}
        },
