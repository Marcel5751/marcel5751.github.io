Simplified Package and version management with mise-en-place

Tags: #linux #windows #packages

When working on several projects simultaneously, it can sometimes be a hassle to manage all the programming languages and tools, especially if different versions of the same tool are required. This can lead to a very confusing setup with multiple versions installed via different mechanisms, annoying environment variable handling and so on. There are several tools, which address this issue, but mise-en-place especially struck my eye as it covers all my needs and is straightforward to install and use. In this article I have collected some general guidance and hints about specific problems I encountered for some particular SDKs and terminal environments.

As always, please follow the official guides as the primary source of truth. This is meant to provide additional advice for specific problems that arose for me.

Setup

mise-en-place is cross-platform and works on basically all popular terminals. Still, there are some special cases, where some research and trial-and-error was needed to get it running.

Ubuntu / WSL

After installing as per the docs, make sure to execute

echo 'eval "$(~/.local/bin/mise activate bash)"' >> ~/.bashrc

In my case, the software was acutally installed under /usr/bin/mise, which means the path in the command above needs to be adjusted.

PowerShell

The PowerShell equivalent of the .bashrc script running when a shell session starts, are PowerShell profiles. Here is how to set it up on Windows:

if (!(Test-Path $PROFILE)) { New-Item -ItemType File -Path $PROFILE -Force }
Add-Content -Path $PROFILE -Value '(&mise activate pwsh) | Out-String | Invoke-Expression'

This will create a file Microsoft.PowerShell_profile.ps1 in your C:\Users\<USER_NAME>\Documents\PowerShell directory.

Git bash on Windows

This is by far the most troublesome to set up, as git bash, or more precisely the MinGW shell which it is based on, has a particular way to load its environment variables, which are essential for mise to function properly.

Especially, if you run git bash from within Intellij, it is not started as a “Login Shell”. In my case, the shell was then not able to find the tools managed by mise.

If not configured correctly, it can also happen that the linux tools shipped with minGW are not available, leading e.g. to errors like bash: command not found: ls.

I was able to get it working in both git bash cases (Login shell or not) by using shims. Put the following content into the ~/.bashrc file:

# Use mise Shims instead of Activation
export PATH="/c/Users/<USER_NAME>/AppData/Local/mise/shims:$PATH"
# IF basic unix commands like ls and cat are not working, explicitly add mingw64 to the path
# export PATH="/c/Users/<USER_NAME>/AppData/Local/mise/shims:/usr/bin:/bin:/mingw64/bin:$PATH"

Since git bash will execute the ~/.bash_profile script on startup, we can put the following contents there to make sure it run the .bashrc script:

[[ -f ~/.bashrc ]] && . ~/.bashrc

Angular CLI fix

Out of the box, the Angular CLI, e.g. ng serve was not accessible after installing it with npm through mise-en-place.

# assuming angular CLI was installed with:
npm install -g @angular/cli@latest

# Hotfix: add folder containing ng shim to path
export PATH="/c/Users/<USER_NAME>/AppData/Local/mise/installs/node/24.14.0/:$PATH"

# permanent fix
mise reshim
# this will generate the 'ng' symlink in Local\mise\shims folder, which we already have in the PATH

Maven

Maven can be installed via the mise-maven plugin.

# installs latest maven
mise install maven

# Or concrete version
mise install maven@3.5.4

mise plugin install maven

mise use maven

General Usage

Here is a list of some of the most useful commands.

# list available versions
mise ls-remote java

# list installed versions
mise ls

# installs latest openjdk 21 versions and sets correct JAVA_HOME 
mise use -g java@openjdk-21

# execute one-off commands with a specific version of a tool, see https://mise.jdx.dev/getting-started.html#mise-exec-run
mise exec java@openjdk-21 -- java --version

# check for errors
mise doctor

# Update Mise itself, see https://mise.jdx.dev/cli/upgrade.html
mise self-update

Plugins for Editors such as Jetbrains IDEs and VSCode are available.
